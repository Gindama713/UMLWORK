#### 任务 A：真实 Nacos 注册发现联调（最高优先级）

这是当前唯一还挂着「不得在报告中写成已完成」的技术项。配置已就绪但从未用真实 Nacos 验证过：

- 各服务 `application.yml` 已有 `NACOS_ENABLED`（默认 false）与 `NACOS_SERVER_ADDR`（默认 `127.0.0.1:8848`）
- `gateway/src/main/resources/application-nacos.yml` 已定义 `lb://服务名` 路由

要做的事：

1. 启动一个 Nacos（standalone 模式即可，端口 8848）
2. 五个业务服务 + 网关设置 `NACOS_ENABLED=true`、`NACOS_SERVER_ADDR=<实际地址>`
3. 要让调用方走服务名发现，需把 `SPACE_SERVICE_URL`、`BILLING_SERVICE_URL`、`PASS_SERVICE_URL`、`ACCESS_SERVICE_URL` **设为空值**；网关用 `--spring.profiles.active=nacos` 启动
4. 在 Nacos 控制台确认六个实例已注册
5. 经网关跑通 `./scripts/smoke-gateway.ps1`，确认业务链路在服务名发现下仍然正确
6. 如果发现代码需要改（Feign 服务名解析、超时、重试配置等），改完必须同步更新 `docs/api-contract.md` 和 `models/13-deployment.puml`，并重新渲染 PNG

**验收标准**：能贴出 Nacos 控制台的实例列表证据 + 经网关的服务名调用成功输出。做不到就如实记录卡在哪一步，**不要写「Nacos 已可用」**。

#### 任务 B：真实故障注入与并发集成测试（次优先）

现有 16 条测试用 H2，其中并发/幂等部分是 mock 或单进程覆盖。文档已明确说明这**不代表分布式故障已验证**。需要补的真实场景：

- **并发占位**：多线程同时对同一车位 `occupy`，断言只有一条成功，其余返回 `SPACE_UNAVAILABLE`
- **幂等支付**：并发对同一账单重复支付，断言只产生一笔成功支付，不重复扣费
- **预约冲突**：并发预约同一车位同一时段，断言只有一个成功
- **断线恢复（重点）**：费用冻结后 billing 不可用 → access 应保持 `EXIT_PENDING_PAYMENT`；billing 恢复后重试必须复用同一 `exit_intent`，**不产生第二张账单、不二次扣费**
- **支付成功但释放失败**：应停在 `PAID_PENDING_RELEASE`，重试释放成功后才 `CLOSED`
- **月卡扣款后支付超时**：确认扣费流水的最终一致性

注意：这些场景需要真实 MySQL 才有意义（H2 的事务与锁行为不同）。如果要引入 Testcontainers 之类的依赖，**先问负责人**。

**验收标准**：每条新测试能说明它验证的是哪个具体故障窗口，以及断言为什么能捕获该故障。
