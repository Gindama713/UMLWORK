## 发现并修复

1. MySQL `DATETIME` 被 JDBC `getTimestamp().toLocalDateTime()` 按本机时区重复转换。access 与 analytics 改用 `getObject(..., LocalDateTime.class)` 读取 UTC 墙钟值；普通停车和报表经真实 MySQL 复测。
2. pass 退款接口实际返回 `RefundView`，access 误按 `ReservationView` 解析。退款已成功时导致后续释放未执行；调用方改为只校验响应成功，并用原记录重试，确认不会二次退款或二次扣款。

## 9 月 28 日接口与逻辑修正

- `space` 新增本地费用冻结：无 ACTIVE 充电才保存 charging_settlement；冻结和新增充电共用车位行锁。修复“账单生成后结束/新增充电而费用遗漏”。新增 CHARGING 车位同时创建配套桩。
- `access` 登记三类请求的键与内容；冻结后保存 exit_intent，再请求 billing。出账失败不能改变时间/异常；寻车返回意图及账单 ID 供页面恢复。符合契约的下游业务 409 保持 409；网络/非法包报 503，不把缺失费用当零。
- `pass` 与 `access` 采用一致的车牌校验；充电和出场输入按数据库微秒精度规范化，避免重试时间比较误判。`analytics` 精确拒绝超过 31 天，preview 不落库，统计排除 ENTERING/ENTRY_FAILED。
- 契约、AGENTS、用例 C、出场顺序/通信/活动图、类图和 ER 图同步；17 张图从源文件重建。
- `scripts/smoke-gateway.ps1` 经真实五库和网关通过：停车 1000 分＋充电 300 分＝1300 分；活动充电拒绝出账、冻结后拒绝充电、同键改内容拒绝；支付失败保留记录，寻车恢复待支付账单，成功后 CLOSED；重试仍 CLOSED，发票 REQUESTED，preview 含真实入场。
- 浏览器独立场景苏A92801：14:00～16:00 账单 1000 分，失败支付保持待支付，成功后释放，模拟发票申请受理。近 24 小时统计展示该场景及 smoke 场景，数字来自 access 只读接口。界面没有自行计算费率或填充虚构收入/车流。
