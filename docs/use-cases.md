## 核心规约草案 A：UC-02 登记车辆入场

- **前置条件**：车场开放；车牌格式可识别；存在可用且类型匹配的车位。
- **基本流**：①输入/模拟识别车牌；②检查同车牌无在场记录；③查询有效预约；④请求车位服务占用一个车位；⑤创建 `PARKED` 停车记录；⑥返回车位楼层、区域和编号。
- **备选/异常**：已有在场记录时拒绝重复入场；无可用车位时提示满位；占位成功而记录创建失败时执行释放补偿；服务不可用时明确失败。
- **后置条件**：恰好一条在场记录；恰好一个对应车位被占用。

## 核心规约草案 B：UC-05 预约车位并预付

- **前置条件**：车牌和预约时段有效；该时段资源可用。
- **基本流**：①输入车辆、时段与车位类型；②校验冲突；③创建待支付预约；④生成预付款请求；⑤支付成功后确认预约并保留资源；⑥返回预约凭证。
- **备选/异常**：时段冲突时拒绝；支付失败或超时不确认；取消、过期或未到场按确认后的规则释放资源。
- **后置条件**：只有支付成功的预约可以成为 `CONFIRMED`，同一资源在重叠时间窗无冲突。

## 核心规约草案 C：UC-03＋UC-04 出场结算

- **前置条件**：存在未关闭停车记录；出场时间晚于入场时间。
- **基本流**：①读取停车和充电明细；②核验预约、月卡权益；③按费率版本试算并生成账单；④展示分项金额；⑤模拟支付；⑥支付成功后关闭停车记录并释放车位；⑦按需申请发票。
- **备选/异常**：支付失败保留待结算状态；重复请求不能重复成功扣款；释放车位失败时记录待补偿状态；异常出场按专门规则处理。
- **后置条件**：已关闭停车记录对应已成功支付的账单，车位最终恢复可用，费用快照可追溯。
